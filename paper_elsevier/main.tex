\begin{abstract}
The spatial queries that dominate point-cloud practice are dense and machine generated: geometry-processing pipelines issue one neighborhood query per point per stage, and hierarchical point networks issue sampling and grouping queries at every layer of every batch, so the index is an inner loop of the application rather than a service for sparse interactive requests. This manuscript introduces a workload-aware framework that synthesizes the point-cloud spatial index for exactly these regimes. Rather than selecting a fixed quadtree, octree, kd-tree, grid, or bounding-volume hierarchy in advance, the framework treats the index as a measured design variable: it captures the query trace a real application issues, generates single, nested, and conditionally activated schemas, builds them over the target data, and selects by replaying the recorded workload, recording the provenance needed for fair comparison. Two application regimes anchor the evaluation --- LiDAR processing pipelines over heritage- and survey-scale scans, where one static index is amortized across per-point stages, and PointNet++-style dataloaders, where the index is rebuilt per block and construction cost is first-class --- together with a boundary study on ray tracing showing that, against a hyper-engineered incumbent structure, the measured search correctly converges to the incumbent. The one-off search cost is amortized over the millions to billions of queries the host application issues.
\end{abstract}
